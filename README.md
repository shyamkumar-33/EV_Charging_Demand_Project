# EV Charging Demand Prediction

## 1. Project Overview

The **EV Charging Demand Prediction** project uses machine learning and time-series forecasting to analyze electric vehicle (EV) charging records and predict charging demand.

The project includes data cleaning, exploratory data analysis (EDA), regression, classification, time-series forecasting, model explainability, and an interactive Streamlit dashboard.

The goal is to explore historical charging patterns, estimate demand from charging-related features, identify high-demand records, and examine future demand forecasts.

## 2. Project Objectives

- Clean and prepare EV charging data for analysis.
- Explore charging demand patterns and trends.
- Build a regression model to predict charging demand.
- Build a classification model to identify high-demand records.
- Forecast charging demand for the next seven days.
- Analyze the features used by the trained models.
- Develop an interactive dashboard for displaying results.

## 5. Dataset

The project uses EV charging records stored in CSV format.

The cleaned dataset is located at:

`data/cleaned_charging_data.csv`

The dataset contains **72,843 records and 19 columns** in the current project setup.

The data includes charging-related information such as timestamps, demand, charger characteristics, and location-related features. The exact columns available depend on the supplied dataset.

## 6. Project Modules

### Module 1: Data Cleaning and Exploratory Data Analysis

Notebook: `notebooks/01_data_cleaning_eda.ipynb`

This module prepares the charging records for modeling.

Tasks include:
- Inspecting the dataset and data types.
- Handling duplicate and missing records.
- Converting date and time columns.
- Exploring charging demand distributions.
- Visualizing demand patterns.
- Creating time-related features.
- Saving the cleaned dataset.

Output: `data/cleaned_charging_data.csv`

### Module 2: Regression Model

Notebook: `notebooks/02_regression_model.ipynb`

Regression predicts a numerical demand value using selected charging-related features.

The notebook evaluates regression algorithms and saves the selected model.

Outputs:
- `models/best_regression_model.joblib`
- `models/regression_results.csv`

The results file contains the evaluation metrics generated by the notebook.

### Module 3: Classification Model

Notebook: `notebooks/03_classification_model.ipynb`

Classification identifies records belonging to a high-demand or lower-demand class.

The current notebook defines high demand using the 75th percentile of the demand values.

The model is evaluated using classification metrics such as accuracy, precision, recall, F1-score, and ROC-AUC where applicable.

Outputs:
- `models/best_classification_model.joblib`
- `models/classification_results.csv`

### Module 4: Time-Series Forecasting

Notebook: `notebooks/04_time_series_forecasting.ipynb`

This module aggregates recorded demand by day and uses Simple Exponential Smoothing to generate forecasts.

The notebook evaluates forecasts against a chronological test set and produces a seven-day forecast.

Outputs:
- `models/forecast_evaluation.csv`
- `models/seven_day_forecast.csv`

Forecast results depend on the dataset, aggregation method, and assumptions used during preprocessing.

### Module 5: Model Explainability

Notebook: `notebooks/05_explainability.ipynb`

This module explores which processed input features have larger model coefficients or feature-importance values.

The results can help explain how the trained regression model uses its inputs. Coefficients and feature-importance scores do not, by themselves, establish causation.

Optional output:

`models/regression_feature_importance.csv`

### Module 6: Interactive Dashboard

Application: `dashboard/app.py`

The Streamlit dashboard provides an interface to:

- View an overview of the cleaned dataset.
- Explore historical demand.
- Enter model inputs and request a regression prediction.
- View the saved seven-day forecast.
- Download the forecast results.

## 7. Installation and Setup

### Prerequisites

Install Python and Visual Studio Code. Python 3.12 was used during project development.

Open the project folder in VS Code and open a terminal in the project root.

### Create a virtual environment

```bash
python -m venv .venv
```

Activate it on Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

If PowerShell blocks activation, select the `.venv` Python interpreter in VS Code and run commands using that interpreter.

### Install dependencies

```bash
python -m pip install pandas numpy matplotlib scikit-learn statsmodels joblib streamlit jupyter ipykernel
```

## 8. How to Run the Project

### Run the Streamlit dashboard

From the project root, run:

```bash
python -m streamlit run dashboard/app.py
```

Open the following address in your browser if it does not open automatically:

`http://localhost:8501`

### Test the saved models

Run:

```bash
python src/test_models.py
```

This script loads the trained regression and classification models and attempts to generate predictions using a record from the cleaned dataset.

### Run the notebooks

Open the `notebooks` folder in VS Code and execute the notebooks in numerical order, starting with data cleaning and EDA.

The cleaned dataset and model files should be generated before running the dashboard or model test scripts.

## 9. Model Evaluation

The project stores model evaluation results in CSV files so the results can be inspected and compared.

| Model type | Evaluation information |
|---|---|
| Regression | Regression metrics recorded in `regression_results.csv` |
| Classification | Accuracy, precision, recall, F1-score, and applicable ROC-AUC |
| Time-series forecasting | MAE and RMSE recorded in `forecast_evaluation.csv` |

**Important:** Actual metric values should be copied from the generated result files after evaluation. No accuracy or error values are claimed here without inspecting those files.

## 10. Limitations

- Predictions depend on the quality and representativeness of the available dataset.
- Model predictions are estimates and may not match real-world charging demand.
- The seven-day forecast depends on historical demand patterns and the assumptions used during aggregation and interpolation.
- The classification threshold is based on the dataset's demand distribution.
- Feature importance and model coefficients should be interpreted carefully.
- Further validation on unseen data and data from different locations or time periods may be needed before real-world deployment.
